# 嗅辨溯源 · 移动端 MVP

用"人的嗅觉 + 手机定位 + 当地气象"粗略反推污染源方位，不依赖浓度监测数据。

## 在线使用（推荐）

手机浏览器直接打开：**https://lfc0902.github.io/odor-source-mobile/**

- HTTPS 页面，手机可以正常弹出定位授权，天气、地图都不依赖电脑。
- 添加到主屏幕即可像 App 一样全屏使用：
  - Android Chrome / Edge：菜单 →「添加到主屏幕」/「安装应用」
  - iPhone Safari：分享 →「添加到主屏幕」
- 首次打开需要联网；之后页面壳会离线缓存（地图瓦片和天气仍需网络）。

## 本地启动（开发用）

双击项目根目录的 `启动手机版.bat`，然后：

- 电脑本机：http://localhost:8123
- 手机（同一 Wi-Fi）：http://电脑局域网IP:8123

电脑 IP 用 `ipconfig` 查看（IPv4 地址）。首次运行 Windows 防火墙可能弹窗，选"允许"。

## 使用流程

1. 打开页面 → 自动定位（或点击地图手动标点）
2. 自动显示当地天气：风向、风速、气温、湿度
   - 主源 Open-Meteo（免 key，8 秒超时）→ 失败自动切 wttr.in（12 秒）
   - 两个源都失败时，点「手动」输入风向（0–359°）和风速（m/s）继续使用
3. 按当下闻到的情况选择气味等级 1–5
4. 点击「提交嗅辨记录」→ 地图上画出**上风向扇形**和**估算位置圈**
5. 换几个位置重复提交，多个扇形交叠处即最可能的污染源区域

## 巡测模式（走动观测）

点「开始巡测」后：

- 页面持续跟随 GPS，并画出走过的轨迹（金色箭头 + 蓝色轨迹线）。
- 每隔约 45 秒（或你闻到明显变化时）选择等级提交一次，记录会自动带上巡测标记。
- 任意两点之间如果 **气味更强**，就说明那个方向更靠近源。页面把所有可比点对做加权平均，给出「**气味增强方向**」箭头与一致性：
  - 一致性接近 1：所有点对方向一致，可信；
  - 一致性偏低：建议再走几个点，或换方向交叉验证。
- 只比较间距 ≥ 40 米的点对；两次观测间风向变化超过 60° 的点对会被忽略（避免把风的变化当成源的方向）。
- 「结束巡测」后箭头保留，可继续补充普通记录，融合图会把巡测点一起参与计算。

## 数据、会话与调参

- **自动保存**：每次提交/删除记录都会写入本机（localStorage），刷新或关闭页面后重新打开会自动恢复记录、融合热区和评估历史。
- **单条删除**：记录右侧「×」可删除该条，融合结果会立即更新。
- **导出**：
  - `导出 CSV`：时间、坐标（WGS-84）、等级、风向/风速、风场一致性、定位精度、巡测编号，带 BOM 可直接用 Excel 打开；
  - `导出 GeoJSON`：记录点 + 模型峰值点 + 80% 概率区域外接矩形 + 气味梯度方向，可直接拖进 QGIS/ArcGIS。
- **对照评估**（评估模式）：
  1. 先在地图上点选已知的真实污染源位置（紫色星标）；
  2. 点「计算评估」，页面按格点概率判定真值是否落在 50%/80% 概率区域，并给出与峰值的距离和方向偏差；
  3. 结果会保存在本机，可「导出评估」成 CSV，用于多次实验的命中率统计（答辩/报告用）。

## 风场稳定性

刷新天气时会额外请求近 6 小时逐时风，计算风向一致性 R（按风速加权，1 = 完全一致）：

- ≥ 0.75：天气栏绿色提示「风向较稳定」，σ 约 25–30°；
- 0.45–0.75：提示「有摆动」，σ 放宽到约 30–36°；
- < 0.45：提示「变化较大」，σ 放宽到约 36–45°，融合可信度相应降级；
- 风速 < 0.5 m/s 时至少放宽到 45°（静风时方向本身不可信）。

每条记录保存当时的风场一致性；之后即使天气变化，融合仍按「当时有多确定」来加权。

## 多条记录综合估计

从第 2 条记录开始，页面底部会出现「综合估计」卡片，地图叠加**热区**（颜色越红表示模型概率越高）和**红点**（模型最可能点）：

- **融合方法**：每条记录看作一个"方向 × 距离"的似然：方位角按高斯分布（σ=25°），距离在所选等级的区间内权重为 1、区间外按高斯软衰减。各条记录的似然逐格点相乘、归一化，得到一张相对概率网（128 行格点）。
- **50% / 80% 区域**：按格点概率从高到低累加，覆盖总概率 50% / 80% 的最小格点集合，给出面积（公顷）与范围。
- **可信度标签**：综合 80% 区域相对最小扇形是否集中、记录条数、是否静风、观测期间风向是否稳定给出「高 / 中等 / 低」。记录少于 3 条最多给「中等」；两条扇形方向矛盾时会提示"可能矛盾，或存在多个污染源"；风场摆动较大时方位不确定度自动放宽并降级。
- 卡片上的「隐藏热区」可临时关闭叠加，「聚焦」缩放到估计范围。

> **重要说明**：热区概率是**模型的相对评分**，不是实测置信度。模型假设"风向上游就是源"、每级气味对应固定距离区间、各记录相互独立。风向变化、多个污染源、室内/低风速场景下都会失真，结果仅作现场排查的参考，不能当作精确坐标。

## 定位不准怎么办

页面会显示定位精度（± 米）。连续采样 8 秒取最准的一次，精度 ≤ 20 米自动结束。

1. **手机系统里允许「精确位置」**：Android 12+/iOS 13+ 的定位授权有「精确 / 大致」开关，网页拿不到精确位置时误差可达公里级。
2. **不要用微信内置浏览器打开**：微信 WebView 常用网络定位，误差大且可能返回高德 GCJ 坐标。点右上角「…」→「在浏览器打开」。
3. **一键校准**：如果蓝点与真实位置有稳定的偏移（常见是约 500–600 米，方向基本一致，多为设备返回 GCJ 坐标被再次转换），点「校准」，再在地图上点一下你此刻的真实位置。偏移会保存在本机，之后自动修正；按「清除校准」可恢复。
4. 临时使用可直接点地图任意位置手动标点（显示「手动标点」）。

## 关键点

- **手机定位需要 HTTPS**。局域网 `http://IP:8123` 下浏览器不会弹出定位授权，此时点地图手动标点即可，天气与溯源功能不受影响。（要真机自动定位，需要 HTTPS 隧道或打包成 APK 使用原生定位。）
- **地图坐标系**：高德瓦片是 GCJ-02，手机 GPS 是 WGS-84。`js/coords.js` 做了双向转换：内部几何计算全部用 WGS-84，只在绘制和点击时转换，实测误差 < 1 米（`test/coords.test.js`）。
- 高德瓦片为演示用非官方直连；正式发布请改用**高德 JS API（申请免费 key）**，避免版权/授权问题。
- 扇形半角、各气味等级对应的距离区间都在 `js/app.js` 顶部的 `CONFIG` 里，可按实测标定。

## 自测

```bash
# 需先启动静态服务（8123）
node test/geo.test.js       # 球面几何：方位/距离/扇形顶点
node test/coords.test.js    # WGS-84 <-> GCJ-02 转换与往返精度
node test/fusion.test.js    # 多记录融合：方位权重、垂直交叠、矛盾风向、静风、风场放宽
node test/survey.test.js    # 巡测梯度：增强方向、风向变化过滤、风场一致性
node test/exporters.test.js # 导出：CSV 转义/BOM、GeoJSON 结构、评估 CSV
node test/e2e_cdp.js        # 端到端：定位 → 天气 → 提交 → 融合 → 巡测 → 评估 → 导出 → 刷新恢复 → 兜底
```

`e2e_cdp.js` 会自动启动 headless Edge（每次独立调试端口、结束时杀进程树），
产出 `_e2e_before.png` / `_e2e_after.png` / `_e2e_manual.png` / `_e2e_fusion.png` /
`_e2e_survey.png` / `_e2e_restore.png` / `_e2e_tools.png`。
测试 GitHub Pages 线上版：`BASE_URL="https://lfc0902.github.io/odor-source-mobile/" node test/e2e_cdp.js`。
